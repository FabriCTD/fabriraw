FabriRAW v1.0 · CTD Photo Studio

El RAW de tu cámara, en un formato abierto y verificable. Your camera RAW, in an open, verifiable format.

FabriRAW (.fraw) guarda el mosaico Bayer del sensor tal cual, sin interpolar y sin pérdida, con un CRC-32 por bloque y el revelado no destructivo dentro del mismo archivo. CTD Photo Studio convierte tus CR3, NEF y ARW y los revela.

FabriRAW (.fraw) stores the sensor's Bayer mosaic as-is — not interpolated, lossless — with a CRC-32 per chunk and non-destructive develop settings inside the same file. CTD Photo Studio converts your CR3, NEF and ARW files and develops them.

Qué es .frawWhat is .fraw

Un contenedor RAW simple, documentado y sin secretosA simple, documented RAW container with no secrets

Los RAW propietarios (CR3, NEF, ARW) cambian con cada cámara y su estructura se conoce, en gran parte, por ingeniería inversa. FabriRAW toma los datos del sensor y los guarda en un formato cuya especificación completa cabe en una página.

El archivo es una secuencia de chunks con identificador de 4 bytes, longitud y CRC-32, al estilo PNG. Se puede leer con unas decenas de líneas de código en cualquier lenguaje.

Proprietary RAWs (CR3, NEF, ARW) change with every camera, and their structure is known largely through reverse engineering. FabriRAW takes the sensor data and stores it in a format whose full specification fits on one page.

The file is a sequence of chunks with a 4-byte ID, a length and a CRC-32, PNG-style. It can be read with a few dozen lines of code in any language.

VentajasFeatures

Pensado para archivar fotos durante décadasDesigned to archive photos for decades

  • Sin pérdidaLossless

    Muestras de 16 bits tal como salen del sensor. Compresión opcional zlib (RFC 1950), que descomprime exactamente a los mismos valores.

    16-bit samples exactly as they come off the sensor. Optional zlib compression (RFC 1950) that decompresses to the exact same values.

  • Bayer sin interpolarNon-interpolated Bayer

    El chunk DATA guarda el mosaico CFA 2×2 crudo, sin restar el negro y sin demosaico. El revelado se decide después, no al convertir.

    The DATA chunk stores the raw 2×2 CFA mosaic, without black subtraction and without demosaicing. Developing happens later, not at conversion time.

  • CRC por chunkPer-chunk CRC

    Cada bloque lleva un CRC-32 (IEEE 802.3, el de zlib) sobre su ID y su payload. Un bit dañado se detecta y se informa como CorruptChunk.

    Every chunk carries a CRC-32 (IEEE 802.3, zlib's) over its ID and payload. A flipped bit is detected and reported as CorruptChunk.

  • Revelado no destructivoNon-destructive develop

    Exposición, balance de blancos, contraste, saturación y curva viven en el chunk DEV  (JSON), ubicado después de DATA: editar sólo reescribe la cola del archivo.

    Exposure, white balance, contrast, saturation and tone curve live in the DEV  chunk (JSON), placed after DATA: editing only rewrites the tail of the file.

  • Ráfagas .fset.fset bursts

    Un contenedor con el mismo framing y CRC que agrupa N archivos .fraw completos de una ráfaga, con un encabezado JSON SETH.

    A container with the same framing and CRC that bundles N complete .fraw files from a burst, with a JSON SETH header.

  • Open-source MITMIT open source

    Especificación pública y código bajo licencia MIT. Cualquiera puede leer, escribir e implementar el formato sin pedir permiso.

    Public specification and MIT-licensed code. Anyone can read, write and implement the format without asking for permission.

Cómo funcionaHow it works

De la tarjeta de memoria al JPEG, en tres pasosFrom memory card to JPEG, in three steps

  1. 01 · ingest

    Ingesta CR3 / NEF / ARWIngest CR3 / NEF / ARW

    LibRaw (vía rawpy) decodifica el RAW propietario. Se extraen el mosaico, niveles de negro/blanco, balance de blancos, matrices de color y metadatos.

    LibRaw (via rawpy) decodes the proprietary RAW. The mosaic, black/white levels, white balance, color matrices and metadata are extracted.

  2. 02 · .fraw

    Archivo .fraw.fraw file

    Se escriben HEAD, META, COLR, THMB, DATA y END con su CRC. El resultado se puede verificar en cualquier momento con ctd-raw info.

    HEAD, META, COLR, THMB, DATA and END are written with their CRCs. The result can be verified at any time with ctd-raw info.

  3. 03 · develop

    ReveladoDevelop

    Negro/blanco → balance de blancos → demosaico (bilineal o AHD) → matriz de color → exposición y tono → curva sRGB. Los ajustes se guardan en DEV .

    Black/white → white balance → demosaic (bilinear or AHD) → color matrix → exposure and tone → sRGB curve. Settings are stored in DEV .

Línea de comandosCommand line

# 1. CR3 → .fraw
ctd-raw ingest IMG_0001.CR3 -o foto.fraw
# 2. inspect / verify CRC
ctd-raw info foto.fraw
# 3. develop → JPEG (+0.7 EV)
ctd-raw develop foto.fraw -o foto.jpg --ev +0.7
# GUI
ctd-studio

Pipeline de referencia (§5)Reference pipeline (§5)

  1. x = (raw − black[cfa]) / (white − black[cfa]) → [0,1]
  2. WB: x · mult[color]
  3. demosaic: bilinear | ahd
  4. rgb = rgb_cam · rgb
  5. rgb · 2^exposure_ev → highlights / shadows / contrast / saturation
  6. sRGB | power | linear → 8/16 bit

Comparativa honestaAn honest comparison

.fraw frente a otros formatos.fraw vs. other formats

FabriRAW no pretende reemplazar a DNG. DNG también es una especificación pública, es mucho más maduro y lo lee casi todo el software fotográfico. FabriRAW apuesta por la simplicidad, la verificación por bloque y un revelado no destructivo definido en la propia especificación.

FabriRAW does not aim to replace DNG. DNG is also a public specification, far more mature, and read by almost all photo software. FabriRAW bets on simplicity, per-chunk verification and non-destructive develop settings defined in the spec itself.

El formato, byte a byteThe format, byte by byte

Todos los enteros y floats son little-endian, sin padding. Los campos reserved se escriben en cero. El texto (META, DEV) es JSON UTF-8 sin BOM. Documento normativo completo: docs/SPEC.md.

All integers and floats are little-endian, unpadded. reserved fields are written as zero. Text (META, DEV) is UTF-8 JSON without BOM. Full normative document: docs/SPEC.md.

  • • flags bit0 = CRITICAL; the rest reserved (0).
  • • The CRC-32 (IEEE 802.3, zlib's) covers id[4] + payload, not flags or length.
  • • Bad CRC ⇒ CorruptChunk. Unknown and CRITICAL ⇒ UnsupportedCriticalChunk; without CRITICAL it is ignored. Duplicate known chunk ⇒ error.

Layout de un archivo .fraw.fraw file layout

  1. Magic8 B
  2. HEAD20 + 64CRITICAL
  3. META20 + JSONopc.
  4. COLR20 + 112CRITICAL
  5. THMB20 + 16 + Nopc.
  6. DATA20 + w·h·2 (o zlib)(or zlib)CRITICAL
  7. DEV 20 + JSONopc.
  8. END 20 + 0CRITICAL

HEAD siempre primero y END  siempre último. META, COLR y THMB pueden aparecer en cualquier orden entre HEAD y DATA. DEV  va después de DATA. Los IDs son exactamente 4 bytes ASCII: "DEV " y "END " llevan un espacio, y el de color es COLR.

HEAD always first and END  always last. META, COLR and THMB may appear in any order between HEAD and DATA. DEV  goes after DATA. IDs are exactly 4 ASCII bytes: "DEV " and "END " include a space, and the color chunk is COLR.

FAQ

Preguntas frecuentesFrequently asked questions

¿Tengo que borrar mis RAW originales?Do I have to delete my original RAWs?

No, y no lo recomendamos. Conserva siempre los CR3/NEF/ARW originales y una copia de seguridad. El software se ofrece «tal cual», sin garantías.

No, and we don't recommend it. Always keep the original CR3/NEF/ARW files and a backup. The software is provided "as is", without warranty.

¿Se pierde calidad al convertir?Is quality lost when converting?

Las muestras del sensor se guardan sin pérdida y sin interpolar. META conserva los metadatos principales (cámara, lente, exposición, fecha); los bloques propietarios del fabricante (maker notes) no forman parte del formato.

Sensor samples are stored losslessly and non-interpolated. META keeps the main metadata (camera, lens, exposure, date); vendor-proprietary blocks (maker notes) are not part of the format.

¿Qué cámaras son compatibles?Which cameras are supported?

La ingesta usa LibRaw (vía rawpy), así que en principio sirve cualquier RAW con sensor Bayer que LibRaw pueda leer, incluidos CR3, NEF y ARW. La v1 sólo define el mosaico Bayer 2×2: sensores X-Trans o Foveon no están soportados.

Ingest uses LibRaw (via rawpy), so in principle any Bayer-sensor RAW that LibRaw can read works, including CR3, NEF and ARW. v1 only defines the 2×2 Bayer mosaic: X-Trans or Foveon sensors are not supported.

¿Por qué no usar simplemente DNG?Why not just use DNG?

DNG es una gran opción y tiene soporte universal. FabriRAW explora otra cosa: una especificación mínima que cabe en una página, CRC en cada bloque y un revelado no destructivo definido en el propio formato. Ambos pueden convivir.

DNG is a great choice with universal support. FabriRAW explores something else: a minimal one-page spec, a CRC on every chunk and non-destructive develop settings defined in the format itself. Both can coexist.

¿Es gratis? ¿Envía mis fotos a algún lado?Is it free? Does it send my photos anywhere?

Es gratis y de código abierto (MIT). El software funciona sin conexión y no envía datos ni fotos. Esta web no usa cookies ni analítica.

It is free and open source (MIT). The software works offline and sends no data or photos. This website uses no cookies or analytics.

¿Funciona en macOS o Linux?Does it work on macOS or Linux?

El paquete portable es para Windows de 64 bits. La instalación con pip está pensada para ser multiplataforma, pero la versión empaquetada y probada es la de Windows.

The portable package is for 64-bit Windows. The pip install is meant to be cross-platform, but the packaged and tested build is the Windows one.
